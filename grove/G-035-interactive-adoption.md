## Decision and authority

On 2026-09-20 the owner described the desired combination of a local tracker,
linked project knowledge, shared agent workflows, a beautiful TUI and eventual
managed execution. Asked which first adoption milestone mattered most, they
selected a complete shape → implement → review loop on a real hobby project,
initially using interactive harness sessions. After the evidence-based
evaluation and recommendations, they replied: "Yes I agree with all of this."
They then authorized reconciling direction and writing the research/game plan
to disk so later work can be assigned individually.

The [brief](brief.md) is the current direction owner. This
record is its decision receipt, not a second specification. The
[evaluation](G-048-direction-evaluation-review.md) records
evidence; the [roadmap](G-047-adoption-roadmap-plan.md) records order.

## Revisions to earlier choices

- Replace G-002's versions-first default presentation with a project-wide
  current view, preserving explicit source inspection, divergence and exact
  action targeting. G-042 owns the unresolved projection details.
- Target Proposed → Active → Review → Done. For implementation Done means
  accepted and integrated; G-038 owns explicit migration from current meaning.
  Do not relabel old branch-local completion as integration evidence.
- Restore domain terms and linked plans/reports/reviews, keep preparation
  proportional, and avoid universal human approval of technical plans.
- Prioritize an interactive nullsec pilot, with keyborg next; stage native
  shaping, evidence, portability and adoption before managed execution.

## Alternatives and consequences

Keep the working Go/file/Git foundations instead of another restart. A polished
board alone would leave the authoring/review loop incomplete; a runner first
would automate a workflow not yet proven in the intended projects. Retain both
as later investments. Preserve Bench's useful knowledge and role distinctions
without importing its complete taxonomy or fixed orchestration protocol.

This authorizes the selected direction and preparation of work, not a claim
that schema changes have shipped, automatic assignment of every work item,
live nullsec/keyborg migration, or merging/pushing implementation branches.

## Reconsideration

Revisit sequence after the native loop and nullsec pilot reveal actual friction.
Revisit projection rules when concrete ambiguous histories defeat the proposed
policy. Revisit model routing and runtime ownership using bounded trial evidence.
