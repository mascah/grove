**Propose says "We should do this."** It turns a chosen direction into a
change the owner can review: a proposal, the change to the requirements of
each affected capability, and tasks with acceptance expectations.

### 1. Start from what is already said

Use what the owner has said in this conversation, without asking them to
repeat it. From the owner's description below, first read the code and the
documents in the project index that it touches.

### 2. Confirm the scope with the owner

- Say in a few sentences what you understand is being proposed: the
  problem, the intended outcome, what is in scope and what is not, and ask
  the owner to confirm or correct it.
- If several options are still open, ask which one.
- If the direction turns out not to be settled, say so: the work belongs
  back in exploring, not in a proposal that hides the gap.

### 3. Write the change

Write every decision in the proposal, however much room it needs. Each
task names its files and interfaces, as the tasks guide says, so where the
change goes in the code is settled here, not left to whoever builds it.
No estimates.
