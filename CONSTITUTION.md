# Grove constitution

Draft 2026-10-14. Copy into the repository as `CONSTITUTION.md`. It is the
only document whose sentences bind an agent. `grove.md` is direction, the
walkthrough is the spec, this file is the law. Every rule is one line and
numbered so it can be quoted. Changing this file is its own commit with no
code in it, and the owner reads it before any code follows.

Rules restate entries in `decisions.md`: 1 and 10 are D-12 and D-20; 2 and 3 are D-13 and D-21; 4 and 5 are D-02 to D-04; 6 is D-24; 7 is D-01 and D-06; 8 is D-27; 9 is D-15; 11 is D-23; 23 is D-30; 24 is D-28; 22 is D-31; 27 is D-32. The size rules 12 to 18 are new and become decisions when the owner adopts this file.

## Product boundaries

1. Grove prepares instructions and interactive authoring sessions for explore, propose and review. Nothing else launches a process.
2. `implement <change-id>` prints instructions and exits. Grove creates no workspace, launches no session and computes no state for implementation.
3. Implementation progress is a convention in `implementation.md`, written by the implementing agent and read by people. No code reads it until cycles exist.
4. Approval is the proposal being in the target branch. It never means implemented. Merging, committing, saving or ending a session approves nothing.
5. Four meanings stay apart: maintained spec (agreed), change set (approved future work), exploration (findings), observed behavior (evidence). Code enforces the distinction only where a display or instruction would otherwise blur it.
6. Review is `review <id>`, a readout of what a merge would agree to, and `instructions review <id>`. No manifests, provenance records or review document kind until GitHub review exists.
7. Markdown in Git, Git required, no service, no database, no index. Explorations, changes and specs are files under one configured root.
8. `docs/walkthrough.md` is the specification. A command, flag, message or branch exists only if a step in the walkthrough needs it.
9. Thin skills generated by `init` run `<binary> instructions <workflow> ...` in the caller's session and follow the result. They never launch another agent.
10. Sessions launched by Grove are the first increment of the session dashboard in `grove.md` section 11. Nothing more is built on the foreground launch path.
11. Out of scope until the owner writes them in here: cycles, completion, GitHub, tmux dashboard, Codex profiles, cleanup, archiving, autonomous execution.

## Size and shape

12. Budget: 5,000 non-test Go lines and 3,000 test lines, counted by `just check`, which fails above them. Raising the budget is a change to this file.
13. No guard, fallback or error branch without a failure reproduced on the fixture and named in the commit message.
14. A user-facing message is one sentence. Explanation lives in the guides and the walkthrough, not in Go strings.
15. Six packages at most. No interface with one implementation, no converter between two structs that mean the same thing.
16. Dependencies are the standard library plus what the owner lists here: `gopkg.in/yaml.v3`, Bubble Tea, Glamour, `golang.org/x/term`. Nothing else without a change to this file.
17. Tests follow the walkthrough path on real disposable Git repositories. No PTY harness, fake Git, or adversarial-input suite without a reproduced bug.
18. Comments say why, not what. A function whose name and body say what it does has no comment.

## How agents work here

19. Read this file first in every session and every sub-agent brief; quote the rule number for anything called fixed or out of scope.
20. Scope lives here and only here. `AGENTS.md` describes the code and points to this file; it never restates scope.
21. Questions about whether Grove should do something are asked in text, name the rule they would cross, and offer no recommended option. "How should it work" is asked only after "whether" is answered.
22. An owner's answer from a phone or a tap is a lean, not a decision. A decision is the owner's words written into this file, `grove.md` or the walkthrough.
23. Adversarial review is run by the owner, by hand, after a real run. Agents do not invoke it, and a finding gets a fix only with a fixture reproduction.
24. Harness behavior that varies by user settings, such as permission prompts, is never a design input.
25. Decisions in documents are the owner's, in the owner's words, attributed. Agent inference goes under open questions or assumptions to confirm.
26. One walkthrough step per commit, demonstrated on the fixture with the command in the message. No bundling a fix round into a feature commit.
27. `~/GitHub/mascah/grove-legacy`, `~/GitHub/mascah/grove` and `~/GitHub/mascah/bench` are read-only. Copied code is listed in `docs/reuse.md` with path and revision. No remote, push, hook or global install.
